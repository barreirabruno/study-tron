# Task 002 — Study sessions Persistence

## Objective

Create a backend feature to handle study session
Working on database aspect of the feature
Ignore data delivery aspects like http or any other delivery method.

## Context

This study session must bre created in a database table. The database choose for now is SQLITE, because it is simple and attend the demand for structured data in this project.

Study session entity attributes description:
A study session has an id, which is a UUID v7 - The UUID v7 identifier must be generated by the application before persistence. The agent may select a maintained UUID v7-compatible dependency during planning and must record that decision in the plan.
A study session has a start date, which is a timestamp
A study session has a end date, which is a timestamp

Study session entity actions:
A study session is created and its start date is fullfilled
A study session is created with end date with null value

Study session relations:
By now, this table has no relations, it is a stand alone table just tracking study session times
BY now there is no user relation, consider I will run this locally and this application will handle ONE user at a time, no need for user_id relation now.
Each program execution will create a new study session, this will change later
Ending or updating a study session is outside the scope of this task.

Study session table name in SQLITE: study_sessions


## Tooling

Npm install the following tooling

ORM: Typeorm 1.x stable version
Reflect-metadata(ORM depdends on it): reflect-metadata
Databse driver: better-sqlite3(according to docs)

## Database constraints

- Create a physical SQLITE file in the root of the project - database file name - study-tron.sqlite
- Typeorm must NOT synchronize when it starts, let it with migrations
- Entry point dont execute migrations automatically
- Create a command for migration execution in backend package.json

## Code design

- Implementation path apps/backend
- Implement StudySessions entity using Typeorm
- Implement a Typeorm migration for this entity study session
- Implement a StudySessionRepository port that does not depend on TypeORM types.

    Initial methods:

    - create(): Promise<StudySession>
    - findById(sessionId: string): Promise<StudySession | null>

    Implement a TypeORM adapter for this port.

## Temporary data delivery layer

Create a main method which will create a new study session when I execute the program on terminal, dont accept any arguments, dont provide options, just create the study session and finish

## Acceptance criteria

- Dependencies installed in backend workspace
- Synchronize is settled to false
- Migration creates study_sessions table
- study_sessions table has columns id, start_date, end_date
- start_date is filled in study session creation
- end_date is null when a session is created and stay like this, update it is out of scope now
- each program execution creates a new study_session in database
- a study_session registry can be found by id
- sqlite file is created in the project root directory
- physical database is not versioned
- relevant validation passes
